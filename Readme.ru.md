# MaryGuardian

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](LICENSE)

**Локальный сортировщик документов и ассистент для бухгалтеров, учётчиков и небольших юридических практик.**
Укажите папку с PDF, таблицами и текстовыми файлами — программа проиндексирует их, определит счета, договоры,
выписки и другие типы, отследит сроки, найдёт дубликаты и ответит на вопросы по вашей библиотеке с помощью
языковой модели, которая работает **на вашем компьютере**. Ничего не отправляется в интернет.

*Read in English: [README.md](README.md)*

> **Статус: ранняя версия, минимальное рабочее ядро.** Работает целиком на macOS (Apple Silicon). Поддержка Linux,
> тесты и сборка пакетов открыты для вклада — см. [Дорожную карту](#дорожная-карта--нужна-помощь).
> MaryGuardian — помощник, а не бухгалтер и не юрист: ответы ИИ могут быть неверными. Проверяйте результат.

## Что умеет

- **Быстрое инкрементальное сканирование inbox.** Файлы определяются по SHA-256, поэтому переименования, переносы
  и дубликаты находятся. Неизменённые файлы узнаются по индексу в памяти и не открываются повторно; новые хешируются
  параллельно, а запись в SQLite идёт пачками в одной транзакции. Повторный скан 30 000 файлов — доли секунды.
- **Классификация в два шага.** Сначала детерминированные правила (даты, номера, суммы, валюта, компания, срок),
  затем локальная LLM: тип, отправитель и краткое описание. Ответы модели кешируются, повторная классификация не
  повторяет работу. Название компании от модели принимается, только если дословно есть в тексте.
- **18 типов документов → коллекции** (счета, чеки, кредит-ноты, предложения, заказы, договоры, банковские выписки,
  зарплата, налоги, страхование, коммунальные, юридические, удостоверения, медицинские, сертификаты, отчёты, письма,
  прочее). Можно добавлять свои коллекции с ключевыми словами. Пустые коллекции в боковой панели скрыты.
- **Сроки и очистка.** Просроченные и истекающие в течение 30 дней, возможные дубликаты, документы на проверку,
  файлы, пропавшие из inbox. Программа **никогда не изменяет и не удаляет** ваши файлы.
- **Вопросы к библиотеке.** Ответ строится только по карточкам документов (поиск выполняется в коде, модель больше
  ничего не видит), со ссылками `[id]`.
- **Черновик по одному документу.** Извлечь → черновик (например, претензия) → проверка человеком → утвердить → экспорт.
- **Экран Activity.** Показывает, сколько работы сэкономили кеши: файлы без повторного чтения, хеши, вызовы ИИ и
  попадания в кеш, коммиты в базу.

### Поддерживаемые входные данные

| Вход | Как |
|---|---|
| PDF с текстовым слоем | MuPDF |
| Текст, CSV, XML, JSON (UTF-8 / UTF-16 / Windows-1251) | встроенный ридер |
| DOCX, XLSX, PPTX, ODT, ODS | встроенный ридер (ZIP + XML через архивный API MuPDF) |
| Сканы в PDF | необязательный OCR локальной vision-language моделью (`--ocr-model`, `--ocr-mmproj`); результат всегда помечается на проверку |
| Отдельные изображения (JPG/PNG), старые `.doc`/`.xls` | **пока не поддерживаются** — хорошие задачи для новичков |

## Модель безопасности

`Guardian` — единственный контрольный пункт между моделью и пользователем:

- **Белый список действий** (default-deny); чтение только из `inbox/`, запись только в `output/`; симлинки и слишком большие файлы отклоняются.
- **Поиск PII** (карты с проверкой Луна, SSN, IBAN, e-mail, российские ИНН/СНИЛС …) до показа результата.
- **Эвристики prompt-injection** по тексту документа; текст нейтрализуется перед попаданием в промпт.
- **Человек в контуре:** черновик нельзя экспортировать без утверждения.
- **Журнал аудита** всех решений в `logs/audit.jsonl`.
- Веб-интерфейс слушает **только 127.0.0.1**, требует токен на каждый запуск, проверяет `Host` и `Origin`, отдаёт строгий CSP.

Это эвристики, а не гарантии. О найденных уязвимостях см. [ниже](#сообщить-об-уязвимости).

## Быстрый старт (macOS, Apple Silicon)

Нужно: инструменты командной строки Xcode, `mupdf` из Homebrew, SQLite (системный), сборка
[llama.cpp](https://github.com/ggml-org/llama.cpp) с `mtmd` в `third_party/llama.cpp` и
`nlohmann/json.hpp` в `third_party/nlohmann/`.

```bash
brew install mupdf
git clone --recurse-submodules https://github.com/Khamit/MaryGuardian.git && cd MaryGuardian

# llama.cpp (проверено на коммите: <УКАЖИТЕ>) — API часто меняется, зафиксируйте версию
cd third_party/llama.cpp && cmake -B build -DGGML_METAL=ON && cmake --build build --config Release -j && cd ../..

make                 # соберёт ./MaryGuardian
make install-web     # скопирует web/index.html в mg_workspace/web
```

Интерфейс использует [Bootstrap Icons](https://icons.getbootstrap.com/) (MIT): положите их в
`mg_workspace/web/vendor/bootstrap-icons/` (без них страница работает, просто выглядит проще).

```bash
# без модели работают скан, правила, поиск, коллекции, очистка
./MaryGuardian --workspace mg_workspace

# с моделью (любая instruct GGUF в формате ChatML; разрабатывалось на Qwen)
./MaryGuardian --workspace mg_workspace --model /path/to/model.gguf --port 8080

# необязательный OCR для сканов
./MaryGuardian --workspace mg_workspace --model /path/to/model.gguf \
               --ocr-model /path/to/ocr.gguf --ocr-mmproj /path/to/mmproj.gguf
```

Положите файлы в `mg_workspace/inbox/`, откройте <http://localhost:8080>, нажмите **Scan inbox**.
Веса моделей **не входят** в репозиторий, у них свои лицензии.

> **Приватность:** `mg_workspace/` содержит метаданные и описания ваших документов и журнал аудита.
> Никогда не коммитьте её. Приложенный `.gitignore` её исключает.

## Структура проекта

```
MaryGuardian/
├── main.cpp                  точка входа, разбор аргументов
├── Makefile
├── core/
│   ├── Guardian.*            белый список, ограничение путей, PII, утверждение, журнал
│   ├── Safety.hpp            разрешённые действия, определение формата, PII-шаблоны
│   ├── Verifier.*            эвристики prompt-injection
│   ├── Db.*                  обёртка SQLite: кеш statements, пакетные транзакции, кеши в RAM
│   ├── Indexer.*             конвейер скан → классификация → OCR, индекс в RAM, статистика запуска
│   ├── Extract.*             извлечение полей по правилам + таблица типов документов
│   ├── DocReader.*           текст из Office / текстовых / XML файлов
│   ├── PdfToolEngine.*       MuPDF: чтение, рендер, правка
│   ├── ModelRuntime.*        генерация текста через llama.cpp
│   ├── OcrEngine.*           OCR vision-language моделью (llama.cpp mtmd)
│   └── Library.*             операции пользователя: список, правки, коллекции, очистка, вопросы
├── task/BookkeeperTask.*     сценарий «один документ»: извлечь → черновик → утвердить
├── server/HttpServer.*       loopback HTTP-сервер и JSON API
├── tests/guardian_test.cpp   `make test`
└── web/index.html            одностраничный интерфейс
```

Рабочая папка (создаётся при запуске): `inbox/`, `output/`, `logs/audit.jsonl`, `library.db`, `web/`.

## Принцип проектирования

> Не спрашивай, как выполнить работу быстрее. Сначала спроси, можно ли вообще её не выполнять. Если нет — можно ли
> выполнить один раз. Если нет — заранее. Если нет — только для изменившегося. Если нет — на более дешёвом уровне
> системы. И только потом оптимизируй саму операцию.

На практике: неизменённые файлы не открываются повторно, SHA-256 считается один раз для каждого состояния файла,
SQL — это хранилище, а не рабочая память, записи идут пачками, ответы модели кешируются. Учитывайте это в своих правках.

## HTTP API

Все вызовы `/api/*` требуют заголовок `X-Auth-Token` (встроен в отдаваемую страницу). JSON на входе и выходе.

```
GET  /                      интерфейс
GET  /api/status            состояние сценария «один документ», загружена ли модель
GET  /api/audit             журнал Guardian
POST /api/upload|draft|approve|edit|export      сценарий «один документ»
POST /api/lib/scan          запустить скан
POST /api/lib/scan_status   прогресс, отчёт, статистика запуска, версия данных
POST /api/lib/list|doc|update|collections|collection_save|collection_delete|resort
POST /api/lib/companies|company_rename|profile_get|profile_set|cleanup|ask
```

## Дорожная карта / нужна помощь

- **Порт на Linux:** заменить CommonCrypto SHA-256 (OpenSSL или маленькая встроенная реализация), CPU/CUDA, CMake.
- Принимать **отдельные изображения** (JPG/PNG) — сейчас определитель формата отклоняет их до OCR.
- **Наблюдатель за файловой системой** (FSEvents / inotify) вместо ручного пересканирования.
- Языковые пакеты: форматы дат, формы компаний, ключевые слова для DE / FR / ES / RU …; локализация интерфейса и промптов.
- **Тесты** для правил `Extract`, логики скана `Indexer` и `Db`.
- Старые `.doc` / `.xls` (OLE2), `.eml` / `.msg`.
- Упаковка (`.app` / нотаризованный `.dmg`), экспорт коллекций в дерево папок.

**Добавить категорию документов — одна строка** в `docTypes()` в `core/Extract.hpp`
(и по желанию правила в `Extract.cpp`). Подсказка модели, проверки, коллекции и интерфейс подхватят её сами.
